# Удалённые настройки PlaySpace

После установки клиента с поддержкой удалённых настроек ссылки, объявления и данные можно менять без следующего обновления EXE. Ранее опубликованная 2.0.0 этой возможности не имеет: её пользователям требуется одно обновление приложения.

Лаунчер загружает подписанный набор с `https://raw.githubusercontent.com/d3a0g/playspace-releases/main/remote/stable/manifest.json`. Отдельный сервер и VPS не нужны. Источники для редактирования находятся в `PlaySpaceNext/remote` основного репозитория.

## Что можно менять

| Файл или поле | Возможность |
| --- | --- |
| `config.json`, `links` | Ссылки Robokassa RU/EN, Telegram, страница проекта и оферта. |
| `config.json`, `features` | Доступность уже реализованных рекомендаций, скидок, мастерской, сети, звуков, графики, UniversalDLSS5, большого экрана, цитат, объявлений и добровольной поддержки. |
| `config.json`, `branding` | Цвет акцента, слоган RU/EN, PNG-логотип в base64 до 256 КиБ и 512×512. |
| `config.json`, `timing` | Интервал проверки конфигурации 300–86400 секунд, TTL рекомендаций 300–86400 секунд и Workshop 60–3600 секунд. |
| `config.json`, `tools` | Названия и описания существующих инструментов, отдельно RU/EN. |
| `announcements.json` | До 20 текстовых объявлений с расписанием, переводами и ссылкой на разрешённое назначение. |
| `translations/ru.json`, `translations/en.json` | Переводы: ключ — исходный русский текст интерфейса, значение — новый текст. |
| `catalogs/recommendations.json` | До 5000 игр со Steam ID, названием и категориями. Актуальный Steam-рейтинг продолжает дополнять каталог. |
| `catalogs/mod-adapters.json` | Названия, подсказки и доступность существующих адаптеров. Для отключения убрать адаптер из списка. |

Пути установки модов, типы адаптеров, их идентификаторы и исполняемые файлы остаются встроенными. Новые правила установки, код, команды, админ-права, ключи обновления и новые функции требуют изменения приложения. Секреты и персональные настройки не передаются через этот канал.

Отключение функции препятствует новым запросам к ней. Уже запущенная операция не прерывается автоматически. Настройки пользователя (язык, библиотека, выбранная тема, уменьшение анимации и т. п.) не перезаписываются. Приоритет пользователя сохраняется, например цитаты нельзя включить поверх его выключенного переключателя.

## Изменение и публикация

1. Отредактировать нужные JSON-файлы в `PlaySpaceNext/remote`.
2. Собрать клиент с тем же публичным ключом, если готового валидатора ещё нет.
3. Подписать и проверить набор. Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Publish-RemoteConfig.ps1
```

Команда создаёт `artifacts/remote-config/stable/manifest.json` и читаемую копию содержимого `payload-preview.json`. Для проверки готовым клиентом:

```powershell
& 'artifacts/remote-config/app/LauncherPlaySpace.exe' --verify-remote-config 'artifacts/remote-config/stable/manifest.json'
```

Для публикации на GitHub:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Publish-RemoteConfig.ps1 -Publish -VerifierExecutable 'artifacts/remote-config/app/LauncherPlaySpace.exe'
```

Инструмент проверяет набор тем же нативным валидатором, который использует приложение, и отправляет через GitHub API в `playspace-releases` только подписанный manifest. При обновлении проверяется SHA предыдущего файла, чтобы не затереть параллельную публикацию. Рабочие изменения, приватный ключ, установщики и канал обновления EXE не публикуются этой командой. Требуется настроенный GitHub CLI.

Для ограничения версий клиента использовать `-MinimumClientVersion` и при необходимости `-MaximumClientVersion` в формате `2.0.0`. Редакция автоматически увеличивается с учётом опубликованной. Для отката содержимого публикуется прежний текст с **новой, большей редакцией**. Повторное использование номера с другим содержимым отвергается клиентом.

Подпись действует до 90 дней (`-ValidDays`). До истечения срока набор нужно переподписать и опубликовать с новой редакцией. Срок выбран явно: старый корректный набор не может бесконечно воспроизводиться вместо актуального.

## Работа клиента

Клиент сразу читает локальный подписанный кеш и проверяет обновления в фоне, не задерживая открытие окна. Встроенный интервал — 30 минут; ручная проверка доступна в «Настройки → Настройки проекта». Повторные ручные сетевые запросы ограничены интервалом 30 секунд. Изменения интерфейса применяются при очередном чтении состояния, обычно в пределах 30 секунд после загрузки.

В офлайн-режиме сетевой запрос не выполняется. При сетевой ошибке или неверной подписи остаётся последняя проверенная и непросроченная копия. При отсутствии пригодного кеша или истечении подписи используются встроенные настройки. Их платёжные ссылки остаются значениями из сборки. Не следует использовать этот канал для сведений, которые обязаны оставаться актуальными даже после длительного отсутствия сети.

Состояние и редакция показаны в настройках. Оферта остаётся отдельным документом; конфигурация содержит ссылку на неё и не изменяет её текст.

## Подпись и ограничения

Набор упаковывается в JSON-конверт с `payload` и `signature` в base64. Подписываются точные байты `PlaySpaceRemoteConfig/v1\n` и UTF-8 payload; алгоритм RSA PKCS#1 v1.5 / SHA-256. Вся конфигурация, переводы и каталоги находятся внутри подписанного payload, поэтому отдельные незаверенные файлы по сети не применяются. Максимум payload — 2 МиБ, конверта — 4 МиБ.

Публичный ключ встроен в `PlaySpaceNext/src-tauri/remote-public-key.xml`. Отдельный приватный ключ защищён Windows DPAPI текущего пользователя в `.secrets/remote-config-authority.dpapi`. Он не совпадает с ключами updater и администратора. Инициализация `-Initialize` выполняется один раз и отказывается перезаписывать существующий ключ. Потеря ключа потребует обновления клиента с новым публичным ключом; файл DPAPI сам по себе не переносится на другую Windows-учётную запись.

Клиент проверяет подпись, схему, совместимость, сроки, редакцию, размеры, URL и разрешённые поля. Произвольные JS, HTML, CSS, команды, пути записи и выдача прав через этот канал не поддерживаются. Внешние ссылки открывает нативный код по фиксированным назначениям. Уведомления выводятся обычным текстом React, а не HTML.

## Проверки для разработчика

Нативные тесты включают неверный ключ, изменение payload, сроки, совместимость, запрещённые ссылки и поля, диапазоны параметров, откат редакции, безопасные каталоги, повреждённый кеш и офлайн-поведение. Тесты TypeScript проверяют применение переводов и настроек без изменения языка пользователя, сохранение снимка после ошибки IPC и открытие фиксированного назначения.

Для владельца ключа предусмотрен отдельный сценарий настоящего WebView2/IPC. Создать **изолированный тестовый** подписанный набор и выполнить проверку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& ./tools/New-RemoteConfigTestFixture.ps1; node PlaySpaceNext/tests/remote-config.cjs"
```

Скрипт задаёт `PLAYSPACE_REMOTE_FIXTURE` в дочерней PowerShell-сессии, где затем запускается тест. Тестовая редакция 10000 никогда не публикуется; используется только в отдельном временном профиле. Проверяются RU/EN, подписанный кеш, текст объявления без выполнения HTML, ссылки, каталоги, отключённая функция в Rust, оформление, настройки и возврат к встроенным данным при повреждённом кеше. Основной пользовательский профиль не затрагивается.

После публикации канала отдельная явная сетевая проверка `node PlaySpaceNext/tests/remote-live.cjs` проверяет загрузку настоящего подписанного набора с GitHub, применение без перезапуска окна и сохранение офлайн-копии. Платёжные страницы не открываются, переводы денег не выполняются.
